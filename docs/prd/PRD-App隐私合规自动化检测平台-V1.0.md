## 1. 产品概述

### 1.1 背景与问题

国家互联网信息办公室等四部门联合发布的《App违法违规收集使用个人信息行为认定方法》（国信办秘字〔2019〕191号）按第一至第六条明确了六大类违法违规收集使用个人信息行为的认定标准，是 App 个人信息保护监管执法的重要依据。App 上线前如未完成合规自查，将面临通报、下架等处罚风险。

然而 App 业务逻辑日益复杂，隐私收集行为大量隐藏在深层业务页面与特定交互场景中，现有手段存在明显短板：

1. **人工检测效率低**：单款 App 全流程合规检测依赖专业人员数天时间，成本高、无法规模化。
2. **传统自动化工具覆盖率不足**：固定脚本、盲目遍历仅覆盖首页、设置页等表层页面，深层场景大量漏检。
3. **整改指导缺失**：现有工具输出问题清单后，开发者仍需自行研究如何修复，闭环周期长。

### 1.2 产品定位与目标

**定位**：面向企业开发者的 App 隐私合规一站式自查平台。通过「大模型 + Appium」AI 深度页面遍历技术，自动完成 App 全场景隐私行为检测，对标《认定方法》六大类违规情形输出可作为整改依据的检测报告、完整证据链与整改建议。

**核心目标**：

1. **检测能力对标法规**：完整覆盖《认定方法》六大类违规情形，输出含法规条款、风险等级、证据链、整改建议的检测报告。
2. **AI 深度自主遍历**：替代传统固定路径遍历，页面覆盖率较传统方案提升 50% 以上，可深入 3 级及以上业务页面。
3. **全流程自动化**：APK 上传后，自动完成安装、遍历、行为监控、合规判定、报告生成，全程无人值守。
4. **降低整改成本**：每条违规附针对性整改建议，支持整改后复检对比，形成合规闭环。

### 1.3 范围说明

**本期（V1.0）范围**：

- Web 平台（无登录，3 页面：检测首页/任务进度/报告详情；APK 管理、检测任务、检测报告、PDF 导出）
- Android APK 检测，覆盖《认定方法》六大类违规情形
- 两档检测模式：快速模式（约 30 分钟）、深度模式（1–2 小时）
- 合规评分、证据链、整改建议、PDF 报告导出

**本期不做**（含裁剪项，以 V1.1 变更记录为准）：

- 账号注册登录（V1.0 无登录直接使用）
- Word 报告导出（移至 V1.1）
- 隐私政策结构化字段解析（移至 V1.1，本期仅提取政策原文）
- iOS App、小程序/快应用检测（列入 V2.0）
- 企业多租户与团队协作
- 整改建议中的代码级示例（当前仅方案级建议）
- 分布式设备集群、千级批量检测（当前支持小规模批量排队）

## 2. 用户与场景

### 2.1 目标用户画像

| 画像 | 描述 | 核心诉求 |
|------|------|----------|
| **企业合规工程师** | 负责公司 App 上线前的合规审查，对接监管要求与内部开发团队 | 快速发现违规项、拿到法规依据和证据、推动开发修复 |
| **移动开发负责人** | 负责 App 研发团队，需评估上线风险并组织整改 | 一眼看清合规风险等级、明确整改事项、验证整改效果 |

### 2.2 核心使用场景

**场景一：上线前合规自查**

某金融 App 计划两周后提交应用商店审核。合规工程师上传 APK，选择「深度模式」启动检测。2 小时内拿到报告：合规评分 68 分，检出 3 项高风险违规（含 1 项"未经同意向第三方共享信息"）。工程师将报告导出后在项目评审会上向开发团队逐项说明，开发团队按整改建议修复。

**场景二：整改后复检闭环**

修复完成后，工程师再次上传新版 APK 检测，使用「复检对比」功能确认 3 项违规全部修复、无新增违规，评分提升至 92 分，随包附检测报告提交商店审核。

**场景三：快速风险排查**

新接入一家三方 SDK 后，开发负责人用「快速模式」30 分钟跑一遍核心隐私场景，确认无高危违规后继续开发，避免把问题留到上线前。

## 3. 核心流程

### 3.1 用户主流程

```
注册/登录 → 上传APK → 查看静态预检结果 → 创建检测任务（选行业/档位）
→ 等待检测（实时进度监控） → 查看报告（评分/违规明细/证据链/整改建议）
→ 导出报告 → 组织整改 → 上传新版APK → 复检对比（V1.1）→ 合规闭环
```

### 3.2 系统检测流程（后台）

```
任务入队 → 调度分配模拟器/设备 → 安装App → 静态分析完成
→ 启动 Frida 行为监控 + mitmproxy 流量抓取
→ AI 遍历主循环：页面信息采集 → 页面指纹去重 → 大模型生成操作决策 → Appium 执行交互
   （全程同步监控隐私API调用、网络流量、权限申请行为）
→ 达到终止条件（检测时长上限 / 页面覆盖率阈值 / 连续无新页面）
→ 检测数据汇总 → 规则引擎对标《认定方法》判定 → 生成报告与证据链
```

**说明**：系统检测流程与《AI驱动的App隐私合规自动化检测Agent设计方案》V1.0 的六层架构（基础设施层→资源调度层→检测引擎层→核心决策层→合规判定层→输出层）一致，本 PRD 不重复技术实现细节。

## 4. 功能需求

> 优先级定义：**P0** = V1.0 必须上线；**P1** = V1.1 版本上线；**P2** = 后续规划。
> 所有验收标准均为上线验收的依据，测试阶段须逐条验证。

### 4.1 账号与登录（~~P0~~ **已取消**：V1.0 不做，无登录直接进入检测页，见 0.变更记录 V1.1）

**FR-4.1.1 邮箱注册与登录**

- 描述：用户使用邮箱 + 密码注册账号，邮箱验证通过后激活；激活后可登录。
- 优先级：P0
- 验收标准：
  1. 使用合法邮箱注册，1 分钟内收到验证邮件，激活后可正常登录
  2. 密码强度校验：不少于 8 位，须包含字母与数字，不满足时给出明确提示
  3. 登录失败时提示统一为「邮箱或密码错误」，不泄露账号是否存在
  4. 连续 5 次登录失败后锁定该账号 30 分钟

**FR-4.1.2 密码找回**

- 描述：用户忘记密码时通过注册邮箱重置。
- 优先级：P0
- 验收标准：
  1. 输入注册邮箱后 1 分钟内收到重置链接，链接 24 小时内有效
  2. 通过链接设置新密码后旧密码立即失效

**FR-4.1.3 个人中心**

- 描述：用户可查看/修改昵称、修改密码、退出登录。
- 优先级：P0
- 验收标准：
  1. 修改昵称后全站展示即时生效
  2. 修改密码需验证原密码，修改成功后其他会话登录态失效

### 4.2 APK 管理（P0）

**FR-4.2.1 APK 上传与解析**

- 描述：用户上传 APK 文件，系统校验完整性后自动解析出应用名、包名、版本号、权限清单、SDK 清单。
- 优先级：P0
- 验收标准：
  1. 上传 ≤500MB 的合法 APK，5 分钟内完成解析并展示结果
  2. 上传非 APK 文件（如改名为 .apk 的 zip/txt）时提示「文件格式无效」，不进入任务队列
  3. 解析失败的 APK（加固/损坏）给出明确失败原因，不阻塞其他功能
  4. 权限清单与 SDK 清单与实际人工抽样核对一致率 ≥95%

**FR-4.2.2 静态预检结果展示**

- 描述：上传解析完成后，展示静态预检结果，作为创建检测任务前的参考。
- 优先级：P0
- 验收标准：
  1. 展示应用名、包名、版本号、文件大小
  2. 权限清单标注危险权限（定位、通讯录、麦克风、相机、存储、设备标识等）
  3. SDK 清单标注各 SDK 的数据采集属性（采集哪些个人信息）
  4. 若 APK 内置隐私政策文本，展示提取出的政策原文（结构化字段解析移至 V1.1）

**FR-4.2.3 APK 列表管理**

- 描述：用户可查看历史上传的 APK 列表，支持删除。
- 优先级：P0
- 验收标准：
  1. 列表展示文件名、解析状态、上传时间，支持按时间排序与搜索
  2. 删除 APK 时提示其关联的检测任务与报告将一并删除，用户确认后执行

### 4.3 检测任务（P0）

**FR-4.3.1 创建检测任务**

- 描述：用户选择一个已解析的 APK，配置检测参数后启动检测。
- 优先级：P0
- 验收标准：
  1. 可选择 APK、App 所属行业（通用/金融理财/电商购物/社交通讯/工具/医疗健康/教育/出行等，行业选择影响必要权限判定基准）
  2. 检测档位两档可选：**快速模式**（约 30 分钟，覆盖核心隐私场景）/ **深度模式**（1–2 小时，完整遍历），档位说明与预估时长在界面上明示
  3. 资源池已满时任务进入排队状态，界面明示排队位置
  4. 创建成功后自动开始检测流程，无需人工干预

**FR-4.3.2 任务进度监控**

- 描述：任务执行过程中实时展示当前阶段与关键进度数据。
- 优先级：P0
- 验收标准：
  1. 阶段状态覆盖全流程：排队中 → 环境准备 → 安装 → 静态分析 → AI遍历 → 数据分析 → 生成报告 → 完成/失败，界面高亮当前阶段
  2. AI遍历阶段展示：已覆盖页面数、已触发隐私场景数、当前页面名称、已用时
  3. 任务失败时展示失败原因（如 App 崩溃无法恢复、设备异常）
  4. ~~任务完成后通过站内消息提示用户查看报告~~（已取消：站内消息随账号体系移除，任务完成状态由页面轮询展示）

**FR-4.3.3 任务管理**

- 描述：用户可取消进行中的任务、对失败任务一键重跑。
- 优先级：P0
- 验收标准：
  1. 取消任务后设备资源在 1 分钟内释放
  2. 失败任务重跑自动复用原配置，无需重新填写
  3. 任务列表支持按状态（全部/进行中/已完成/失败）筛选

### 4.4 AI 遍历引擎（P0，核心模块）

**FR-4.4.1 深度页面遍历**

- 描述：基于大模型语义理解的自主遍历，替代传统固定路径遍历，深入 App 深层业务页面。
- 优先级：P0
- 验收标准：
  1. 深度模式下，样本 App 中 3 级及以上业务页面的覆盖率 ≥60%
  2. 页面覆盖率较传统固定路径遍历提升 ≥50%（用 ≥10 个样本 App 对比测试）
  3. 遍历遵循「先深层后广度、优先隐私相关入口」策略

**FR-4.4.2 隐私场景优先触发**

- 描述：遍历过程优先处理与隐私收集相关的交互场景。
- 优先级：P0
- 验收标准：
  1. 出现权限申请弹窗、隐私政策弹窗、同意授权交互时优先处理并完整记录（时间点、弹窗内容、用户选择）
  2. 优先进入个人中心、设置、账号安全、隐私设置类页面
  3. 对样本 App 中已知存在的隐私相关页面，触发率 ≥90%

**FR-4.4.3 遍历健壮性**

- 描述：遍历过程具备死循环防护、崩溃恢复、超时处理与终止机制。
- 优先级：P0
- 验收标准：
  1. 同一页面连续 N 次操作无变化时（N 可配置，默认 3），强制回溯到上一页面
  2. App 崩溃后 2 分钟内自动重启并恢复到崩溃前页面继续遍历
  3. 页面加载超时（默认 15 秒）自动跳过当前操作重新决策
  4. 满足任一终止条件（检测时长上限/最大页面数/连续无新页面阈值）时正常停止，任务不悬挂
  5. 因弹窗导致遍历卡死时自动处理弹窗（关闭/同意/拒绝按策略执行）并继续

**FR-4.4.4 弹窗处理策略**

- 描述：区分系统权限弹窗与 App 内弹窗，采取不同处理策略，保证检测数据准确性。
- 优先级：P0
- 验收标准：
  1. 系统权限弹窗：记录「弹窗出现时间 → 用户选择（同意/拒绝）」完整时间线，用于「同意前收集」判定；默认选择「同意」以继续深入遍历
  2. App 内弹窗：优先关闭无关弹窗（广告、推荐），隐私相关弹窗记录后按策略处理
  3. 弹窗处理不中断遍历主循环

### 4.5 六大类违规检测（P0）

> 对标《App违法违规收集使用个人信息行为认定方法》第一至第六条。每条违规输出统一包含：违规类别、法规条款、风险等级（高/中/低）、证据链索引。

**FR-4.5.1 未公开收集使用规则检测**

- 描述：检测 App 是否公开收集使用规则（隐私政策），及披露内容是否完整、与实际行为一致。
- 优先级：P0
- 验收标准：
  1. 检测隐私政策入口可访问性：首次启动弹窗、注册页、设置页等入口的存在与可达性，无入口的样本 App 检出率 100%
  2. 隐私政策文本结构化提取覆盖 5 类字段：收集的信息类型、收集目的、第三方共享清单、用户权利渠道、投诉举报方式
  3. 披露与实际行为一致性比对：声明收集项与实际 API 调用不一致的样本检出率 ≥90%

**FR-4.5.2 未经用户同意收集个人信息检测**

- 描述：检测同意前的信息收集行为、默认勾选授权、强制索权行为。
- 优先级：P0
- 验收标准：
  1. 同意前隐私 API 调用：基于 Frida 监控与时间线比对，检出「首次同意前」的敏感 API 调用，样本检出率 ≥90%
  2. 默认勾选：授权页存在默认勾选同意项的样本检出率 ≥90%
  3. 强制索权：拒绝授权后 App 退出/无法使用核心功能/反复弹窗索权的样本检出率 ≥90%

**FR-4.5.3 违反必要原则收集无关信息检测**

- 描述：检测收集与业务功能无关的个人信息、超范围、超频次收集行为。
- 优先级：P0
- 验收标准：
  1. 权限与功能匹配度：结合行业基准判断申请权限的必要性，明显不匹配（如工具类 App 申请通讯录）的样本检出率 ≥90%
  2. 超频次收集：同一敏感信息（如定位）在无用户操作触发下 1 分钟内被读取次数超过可配置阈值的样本检出率 ≥90%

**FR-4.5.4 未经同意向他人提供个人信息检测**

- 描述：检测向第三方（SDK/服务器）传输个人信息、跨境传输、共享披露一致性。
- 优先级：P0
- 验收标准：
  1. 流量解析识别请求参数中的个人信息字段（设备标识、定位、手机号等）与接收方域名归属
  2. 第三方 SDK 数据传输：样本 App 中已知 SDK 上报行为的检出率 ≥90%
  3. 跨境传输：数据发送至境外域名的样本检出率 ≥90%
  4. 共享披露一致性：实际传输数据的 SDK 未在隐私政策中披露的样本检出率 ≥90%

**FR-4.5.5 未提供删除/更正个人信息功能检测**

- 描述：检测账号注销入口、信息更正路径及注销障碍。
- 优先级：P0
- 验收标准：
  1. 注销入口：遍历中检索注销功能入口，无注销入口的样本 App 检出率 100%
  2. 注销障碍：注销需线下客服/设置不合理条件（如收取费用、要求提供超出必要的信息）的样本检出率 ≥90%
  3. 信息更正路径：存在个人信息修改入口的 App，正确识别其路径

**FR-4.5.6 未公布投诉举报方式检测**

- 描述：检测 App 内投诉举报渠道的公布情况与有效性。
- 优先级：P0
- 验收标准：
  1. 遍历中检索客服/投诉渠道（帮助页、关于页、设置页），未公布渠道的样本 App 检出率 100%
  2. 公布的渠道做格式有效性校验（邮箱格式、电话位数等），明显无效的检出率 ≥90%

**FR-4.5.7 违规输出统一规范**

- 描述：所有违规判定结果的输出结构统一。
- 优先级：P0
- 验收标准：
  1. 每条违规包含：违规类别（7 类之一）、违规描述、法规条款（《认定方法》对应条目）、风险等级（高/中/低）、证据链索引
  2. 风险等级判定标准在规则库中可配置（规则权重、升级/降级条件）

### 4.6 检测报告（P0）

**FR-4.6.1 报告总览**

- 描述：报告首页展示整体合规状况。
- 优先级：P0
- 验收标准：
  1. 合规评分（0–100 分）：按六大类违规加权扣分（权重与扣分规则可配置），评分与违规明细联动可追溯
  2. 展示违规项总数、按风险等级（高/中/低）与六大类的分布
  3. 展示检测概况：App 信息、检测档位、遍历页面数、触发场景数、检测时长

**FR-4.6.2 违规明细与证据链**

- 描述：每条违规可展开查看详情与完整证据。
- 优先级：P0
- 验收标准：
  1. 违规详情包含：描述、法规依据原文摘录、发生时间、发生页面
  2. 证据链至少包含：页面截图 +（调用栈 或 流量报文）；所有违规 100% 附带证据，证据可直接打开查看
  3. 支持按类别、风险等级筛选违规列表

**FR-4.6.3 整改建议**

- 描述：每条违规附针对性整改建议。
- 优先级：P0
- 验收标准：
  1. 每条违规至少 1 条整改建议，建议针对该 App 的具体问题（如「检测到 X SDK 未在隐私政策中披露，应在政策第三方共享清单中补充 X SDK 及其收集信息与用途」）
  2. 建议为方案级（操作指引），不含代码示例
  3. 建议内容经大模型生成，语言为中文，单条不超过 200 字

**FR-4.6.4 报告导出**

- 描述：支持将完整报告导出为文件。
- 优先级：P0
- 验收标准：
  1. 支持导出 PDF 格式（Word 导出移至 V1.1）
  2. 导出内容包含全部章节：总览、违规明细、证据链（含截图）、整改建议
  3. 导出文件含报告编号、检测时间、App 信息，可作为对外提交依据

### 4.7 复检对比（P1）

- 描述：对同一包名 App 的两次检测结果自动对比。
- 优先级：P1
- 验收标准：
  1. 系统按包名自动关联历史检测，用户可选择任一历史报告进行对比
  2. 对比结果分类展示：新增违规 / 已修复 / 仍存在，并展示合规评分变化
  3. 「已修复」项可一键生成修复确认说明（含前后证据对照）

### 4.8 遍历过程可视化（P1）

- 描述：检测过程中实时展示遍历状态，检测完成后可回放。
- 优先级：P1
- 验收标准：
  1. 检测中实时展示当前页面截图（延迟 ≤30 秒）
  2. 展示遍历路径树（页面层级与跳转关系），可点击节点查看对应页面截图
  3. 展示已触发隐私场景时间线（权限弹窗、API 调用事件）
  4. 任务完成后支持全过程回放

### 4.9 批量检测（P1）

- 描述：一次提交多个 APK 自动排队检测。
- 优先级：P1
- 验收标准：
  1. 单次最多提交 20 个 APK，按提交顺序排队执行
  2. 批量结果以列表展示（App/评分/违规数/状态），支持导出汇总表
  3. 批量任务中单个任务失败不影响其余任务

### 4.10 平台管理（P2）

- 描述：管理员对平台运行参数的管理。
- 优先级：P2
- 验收标准：
  1. 大模型配置：云端 API 的 key、模型选择、调用参数，切换后新任务生效
  2. 检测默认参数管理：各档位时长、并发数、终止条件阈值
  3. 系统状态页：设备池状态、任务队列长度、最近 24 小时任务成功率

## 5. 非功能需求

### 5.1 性能

| 项 | 要求 |
|----|------|
| APK 解析 | ≤5 分钟/个（≤500MB） |
| 快速模式检测 | ≤30 分钟/任务（不含排队） |
| 深度模式检测 | ≤2 小时/任务（不含排队） |
| 报告生成 | 检测完成后 ≤10 分钟 |
| 并发能力 | 单节点 ≥3 个深度任务并行 |
| 页面加载 | 普通页面 ≤3 秒（P95） |

### 5.2 准确性

- 违规判定准确率 ≥90%（误报率 ≤10%），以验证样本集验收（见 6.2）

### 5.3 安全合规（平台自身）

1. 账号安全：密码加盐哈希存储；登录态过期机制；防暴力破解锁定
2. 数据隔离：不同账号的数据严格隔离，任何接口不可越权访问他人任务与报告
3. 数据安全：APK 上传文件加密存储；全站 HTTPS
4. **大模型数据边界**：发送给云端大模型的数据仅限页面 UI 结构文本与截图，**不传输 APK 二进制、检测报告、用户个人信息**；接口层做字段白名单校验
5. 数据删除：用户可随时删除自己的 APK、任务与报告，删除后不可恢复
6. 数据保留：检测结果默认保留 90 天，到期自动清理

### 5.4 兼容性

- 浏览器：Chrome/Edge/Safari 近两年版本
- 检测环境：Android 8.0–14 的模拟器与真机
- 支持主流加固厂商（360、腾讯、梆梆）加固后 APK 的解析（解析失败时明确提示）

### 5.5 可用性

- 平台月度可用性 ≥99%（除计划维护），MVP 阶段单点部署
- 任务成功率 ≥90%（不因系统自身原因失败；App 自身崩溃由遍历引擎恢复机制兜底）

## 6. 成功指标

### 6.1 验收 KPI

| 指标 | 目标值 | 验收方式 |
|------|--------|----------|
| 六大类违规检测覆盖 | 六大类 100% 覆盖，每类 ≥2 条可触发检测规则（V1.1 起扩至每类 ≥5 条） | 规则库评审 |
| 页面遍历覆盖率 | 较传统固定路径遍历提升 ≥50%；深度模式 3 级及以上页面覆盖率 ≥60% | ≥10 个样本 App 对比测试 |
| 判定准确率 | ≥90%（误报率 ≤10%） | 验证样本集（见 6.2） |
| 检测时长 | 快速 ≤30 分钟；深度 ≤2 小时（不含排队） | 样本 App 计时 |
| APK 解析时长 | ≤5 分钟/个 | 同上 |
| 报告生成 | 检测完成后 ≤10 分钟 | 同上 |
| 证据链完整率 | 每条违规 100% 附带证据（截图 + 调用栈或流量报文） | 报告抽检 |
| 任务成功率 | ≥90%（不含 App 自身崩溃导致的失败） | 运行日志统计 |
| 并发能力 | 单节点 ≥3 个深度任务并行 | 压测 |
| 平台可用性 | 月度 ≥99%（除计划维护） | 监控 |

### 6.2 验证样本集要求（验收前提）

- 样本规模：≥50 个 App，覆盖六大类违规，每类 ≥5 个已知违规样本 + ≥5 个合规样本
- 样本标注：每个样本标注已知违规项（类别/位置/触发路径），作为判定准确率的比对基准
- 样本集在开发期同步构建，作为每一阶段验收的固定依据

### 6.3 上线后运营指标（V1.0 不强制）

- 检测报告导出率 ≥60%
- 复检用户占比 ≥30%（V1.1 功能上线后统计）
- 用户对整改建议的「有帮助」评价占比 ≥70%

## 8. 风险与依赖

| 风险/依赖 | 影响 | 应对 |
|-----------|------|------|
| 云端大模型依赖（API 稳定性、调用成本、响应延迟） | 遍历效率与成本波动 | 1. 精简页面输入，只传关键可交互控件；2. 决策缓存，同类页面复用决策；3. 成本预算监控与告警 |
| 大模型决策延迟导致遍历效率低 | 检测时长超目标 | 引入本地小模型做常规决策、复杂场景调用大模型（V1.1 优化项，MVP 先以精简输入+缓存控制） |
| 页面去重不准确导致死循环 | 遍历卡死、覆盖率下降 | 页面指纹多特征加权（Activity+控件+文本哈希），连续重复操作检测强制回溯 |
| 部分 App 控件无法识别 | 覆盖率下降 | 截图+OCR 辅助定位；支持人工标注关键路径作为引导（V1.1） |
| Frida 被 App 反调试检测 | 动态行为漏检 | Frida 隐藏方案；Xposed/LSPosed 备选；流量分析交叉验证 |
| 验证样本集建设滞后 | 准确率无法验收 | 样本集与开发并行推进，作为阶段验收门槛 |
| 云端大模型数据合规风险 | 平台自身合规 | 严格数据边界：仅传 UI 结构文本与截图，接口白名单校验（见 5.3） |
| 设备/模拟器资源投入 | 并发能力受限 | V1.0 单节点 3 并发起步，V2.0 扩展设备集群 |

## 9. 附录

### 9.1 《认定方法》7 类违规对照表

| # | 违规类别（认定方法） | 平台检测能力 |
|---|----------------------|--------------|
| 1 | 未公开收集使用规则 | 隐私政策入口检测、政策文本完整性解析、披露项与实际行为一致性校验 |
| 2 | 未经用户同意收集使用个人信息 | 同意前隐私 API 调用检测、默认勾选检测、强制索权检测 |
| 3 | 违反必要原则收集无关信息 | 权限与功能匹配度检测、非必要信息收集识别、超频次收集检测 |
| 4 | 未经同意向他人提供个人信息 | 第三方 SDK 数据传输检测、跨境传输识别、共享披露一致性校验 |
| 5 | 未提供删除/更正个人信息功能 | 账号注销入口检测、信息更正路径识别、注销障碍检测 |
| 6 | 未公布投诉举报方式 | 客服/投诉渠道检索、联系方式有效性校验 |
| 7 | 未明示收集使用个人信息的目的、方式和范围（官方第二条） | 收集目的/方式/范围披露完整性检测、权限申请时目的告知检测 |

### 9.2 术语表

| 术语 | 说明 |
|------|------|
| APK | Android 应用安装包 |
| AI 深度遍历 | 基于大模型语义理解自主决策的 App 页面遍历方式，区别于固定脚本遍历 |
| 页面指纹 | 基于 Activity 名称、控件特征、文本哈希生成的页面唯一标识，用于去重 |
| 证据链 | 违规判定附带的截图、调用栈、流量报文、时间线等证明材料的集合 |
| 合规评分 | 按 7 类违规加权扣分计算的 0–100 分综合合规评价 |
| 快速模式/深度模式 | 两种检测档位：约 30 分钟核心场景检测 / 1–2 小时完整遍历检测 |
| 同意前收集 | 用户在首次明确同意（如点击隐私政策"同意"按钮）之前发生的信息收集行为 |
| 认定方法 | 《App违法违规收集使用个人信息行为认定方法》（国信办秘字〔2019〕191号） |
