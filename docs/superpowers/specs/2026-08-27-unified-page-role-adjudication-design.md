# 统一页面角色仲裁设计

## 背景

现有遍历器已有 `PageSemantics` 与页面角色优先级，但角色事实仍由 `appium_explorer.py` 内多个独立函数产生。文档阅读、首次同意、登录状态、目标选择和 LLM 提案对同一元素树重复解释，导致同一页面可以同时被视为文档、登录成功和主页面。

案例M的首次同意页证明了该问题：WebView 把“同意”“不同意”和协议链接暴露为有文字与坐标、但 `clickable=false` 的节点；底部导航却是 `clickable=true`。旧同意识别只从可点击短按钮取证，判定失败后，文档、登录、DFS 分支分别继续执行。

## 目标

1. 每次稳定页面观察只产生一个权威页面角色和一个权威目标目录。
2. 所有角色结论带来源、证据和置信度，可在时间线和回放中复核。
3. 遮罩层角色阻断后台页面的登录、文档、DFS 和返回分支。
4. 仅在受限角色中允许由文字加坐标生成的语义点击目标，避免全局坐标盲点。
5. LLM 可以报告结构化角色冲突，但不能直接覆盖确定性证据或执行操作。
6. 无效果操作只归因于当前可操作层，不能污染被遮挡页面的 DFS 记忆。

## 非目标

- 不为案例M或任意包名、Activity、固定标题添加特判。
- 不把 OCR、LLM 或视觉结果单独作为违规证据。
- 不改变拒绝权限优先、人工登录或规则场景的安全边界。
- 不把首次同意页的条款提及计为实际文档阅读。

## 架构

每个稳定观察按以下单向流程处理：

`原始页面(XML/OCR/截图摘要/路径) → PageEvidence → PageRoleAdjudicator → SemanticTargetCatalog → 候选动作 → FinalAction → 结果归因`

主循环、领域决策器、LLM 和 DFS 均只消费 `ResolvedPage`，不得重新扫描原始元素树决定角色。过渡期的旧 `_is_*` 函数只允许作为证据提取器内部私有实现，不能被动作分支直接调用。

## 1. 页面证据模型

新增不可变数据对象：

- `EvidenceSource`：`ui_tree`、`ocr`、`route`、`previous_action`、`runtime_checkpoint`、`llm_hint`。
- `RoleEvidence`：候选角色、来源、强度、命中项、关联节点标识与坐标。
- `PageEvidence`：本轮所有 `RoleEvidence`、遮罩层信息、页面文本摘要和可见控件。
- `ResolvedPage`：角色、作用域、置信度、阻断角色、允许动作、语义目标目录与冲突记录。

强证据包括：Android 系统 Activity、权限窗口、崩溃页、明确同意/拒绝成对短按钮、已验证的文档来源路径、真实输入控件加登录提交控件。弱文本只可补强，不能推翻强证据。

首次同意弹窗的通用判定不依赖 `clickable`：在同一局部几何区域内，出现政策/条款标题或文本、短“同意/接受”语义和短“不同意/拒绝/暂不”语义，即形成同意遮罩证据。文字节点必须具有可用 bounds；没有 bounds 的 OCR 文字只能作为辅助证据。

## 2. 角色仲裁与优先级

`PageRoleAdjudicator` 返回唯一角色，顺序固定为：

1. 系统/外部作用域、应用崩溃。
2. 系统权限弹窗。
3. 首次同意遮罩。
4. 已验证文档正文。
5. 真实登录表单。
6. 未登录个人页。
7. 文档/隐私枢纽与普通业务页。
8. 低价值商业页。

遮罩一旦成立，`document_body`、`login_gate`、`logged_out_profile`、`main_content` 和 `low_value` 都保留为背景候选，但标记为 `blocked_by_overlay`，不参与动作选择。

文档正文必须满足“来源路径为协议入口或文档 Activity/WebView 正文 + 可阅读正文表面 + 未出现同意/拒绝对”的组合；仅含政策关键词、SDK 清单文本或零次滚动都不能产生“已读完”。

登录成功必须有明确成功提示、退出登录，或账户身份锚点；可见“请登录/未登录”或未解决遮罩时，任何已登录推断都被否决。

## 3. 语义目标目录与安全操作边界

`SemanticTargetCatalog` 从 `ResolvedPage` 生成唯一目录。目录项包含：稳定身份、语义类别、来源、bounds、执行方式和风险等级。

- 正常页面只包含可点击或可解析宿主控件的目标。
- `consent_dialog` 可额外包含位于弹窗范围内的坐标目标：协议链接、复选框、同意、不同意。
- 坐标目标必须由可见文本与 bounds 绑定，并在执行后通过语义变化验证；失败后只对该遮罩目标计重试。
- 遮罩存在时后台目标不进入目录，不能被标记 `visited`、`blocked` 或 `no_effect`。
- 未解决首次同意遮罩时禁止 Android `back`；只有显式拒绝策略或恢复策略可退出。

首次同意页的默认策略保持合规检测边界：如存在可审计的独立协议入口，可做一次有界打开验证；若无法可靠打开，记录“入口不可执行”，随后点击同意进入应用，并从设置、个人、关于等枢纽补读文档。不同意不作为常规进入方式，避免应用直接退出。

## 4. LLM 角色冲突协议

LLM 输入只接收 `ResolvedPage` 和目录，不再接收未经仲裁的整棵元素树作为决策依据。正常情况下 LLM 只能对目录内目标提出候选动作。

当 LLM 发现语义矛盾时，可输出：

```json
{
  "action": "role_correction",
  "proposed_role": "consent_dialog",
  "supporting_targets": ["同意", "不同意", "隐私政策"],
  "reason": "可见成对协议决策控件"
}
```

角色纠正不是动作。仲裁器仅在 UI/OCR/几何证据能够复核时采用；否则记录 `role_conflict_unconfirmed` 并触发一次重新观察。连续一次无法确认时转入确定性恢复，禁止重复 LLM `wait` 循环。

## 5. 结果归因、DFS 与检查点

最终动作带 `surface_id`、`role`、`target_id` 和 `execution_layer`。下一次观察依据这些字段归因：

- 遮罩层目标无效果：仅增加遮罩层重试次数，不污染背景目标。
- 背景页在遮罩解除前不更新导航边。
- 文档完成只由文档会话底部确认事件写入。
- 登录等待仅由权威 `login_gate` 触发。

检查点持久化 `ResolvedPage` 的最小可重算事实、未解决遮罩状态、语义目标身份与导航边；恢复后先重观测并重新仲裁，不把旧角色直接当作当前事实。

## 6. 迁移步骤

1. 新建证据、仲裁和目标目录模块，保留 `PageSemantics` 作为兼容输出。
2. 将现有 `_page_semantics` 改为唯一适配入口，删除主循环对 `_is_consent_dialog`、`_document_key`、登录判断的直接分支依赖。
3. 将同意、文档、登录、DFS 和 LLM 输入改为消费 `ResolvedPage`。
4. 将动作效果写入统一归因接口，阻止被遮罩目标写入 DFS 失败记忆。
5. 删除仅用于旧路径的兼容函数和重复状态键。

每一步独立提交、保留现有事件字段，并补充新的 `role`、`evidence_source`、`blocked_by` 字段。

## 7. 回归与验收

先用案例M页面树构造脱敏、通用命名的回放夹具，再覆盖：

1. WebView 内非 clickable 的“同意/不同意”成对节点识别为同意遮罩。
2. 同一页不能同时成为同意遮罩与文档正文、登录成功。
3. 遮罩存在时底部导航不进入 DFS，也不写无效果/耗尽记录。
4. 生成受限同意坐标目标，但普通不可点击文本不生成坐标目标。
5. 零滚动文档不完成；协议提及不等于文档阅读。
6. “请登录”否决已登录结论；未解决遮罩不触发人工登录等待。
7. LLM 角色纠正可被采纳或拒绝，并且不会造成循环等待。
8. 遮罩解除后，原有 DFS 前沿恢复且首次背景目标仍可探索。

验收要求：上述回放通过；既有页面语义、文档、登录、Appium 遍历测试通过；真实设备冒烟仅在服务可用时执行，并单独报告，不以单元测试替代。
